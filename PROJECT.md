# PROJECT.md — дизайн-заметки

## 1. Что это

Агент квалификации лидов для риелторского демо. На вход — заявка покупателя одним текстом. На выходе — карточка лида: балл квалификации 0–100, вердикт HOT / WARM / COLD, извлечённые критерии, топ-3 матча из инвентаря с причинами и агентские заметки.

Дизайн-приоритеты: объяснимость (каждое совпадение можно обосновать), детерминированность (одинаково для видео-демо), офлайн-работа без внешних ключей, масштабирование до 1M листингов без изменения контракта.

## 2. Архитектура пайплайна

`process_lead(text, store)` выполняет четыре шага:

1. **Экстракция** (`extract_offline`) — rule-based парсер: бюджет (с суффиксами `k`/`m` и защита от артефактов вроде «Family of 4»), спальни/ванные, тип объекта, районы, срочность (LOW / MEDIUM / HIGH), профиль покупателя, фичи с разделением на must-have и nice-to-have по маркерам (need / must / require) внутри клауз.
2. **Квалификация** (`qualify_lead`) — аддитивная модель баллов.
3. **Матчинг** — `store.search(criteria)`: жёсткие фильтры (бюджет ×1.05, спальни, тип), затем релевантный скоринг и ранжирование.
4. **Карточка** — топ-3, причины совпадения, заметки агента (tight inventory, capped pool, unsatisfied must-haves).

LLM-экстрактор подключается через `extract_llm()`; сейчас это хук-заглушка, офлайн-ветка остаётся рабочим режимом. Автопереключения по `OPENAI_API_KEY` в текущей версии нет.

## 3. Модель скоринга (актуальные веса)

### Квалификация лида (`qualify_lead`)

| Компонент | Баллы |
|---|---|
| База | 28 |
| Бюджет распознан | +24 |
| Спальни распознаны | +13 |
| Районы распознаны | +10 |
| Must-have фичи | +5 за каждую, максимум 20 |
| Nice-to-have фичи | +4 за каждую, максимум 15 |
| Срочность MEDIUM / HIGH | +3 / +6 |
| Профиль «инвестор» | −8 |
| Итог | клампинг 0–100 |

Ключевое правило: лид без явного тайминга не может быть HOT — при срочности LOW балл жёстко капится на 72, чтобы «не спешу» не перевешивал бюджет и спальни.

Пороги: HOT ≥ 75, WARM ≥ 55, COLD ниже 55.

### Скоринг листинга (`score_listing`)

| Компонент | Баллы |
|---|---|
| База | 25 |
| Цена в бюджете | +25 |
| Цена в бюджете ×1.05 (флаг агенту) | +10 |
| Спальни ≥ запрос | +15 |
| Район из запрошенных | +22 |
| Тип объекта совпал | +10 |
| Каждая совпавшая фича | +8 |
| Отсутствующий must-have | −12 |
| Итог | клампинг 0–100 |

Ранжирование: по убыванию скора, при равенстве — по возрастанию id (детерминированно). В ответ уходят топ-3.

## 5. Хранилища листингов

- **DemoListingStore** — 20 кураторских листингов из `app/data.py` (Остин и пригороды: Zilker, South Congress, Cedar Park и т. д.).
- **LargeListingStore** — синтетика на 1 000 000 листингов в компактных numpy-массивах (int8/int16/int32, битовая маска фич). Ничего не пишется на диск: тот же seed — тот же инвентарь, полная сборка за ~0.1 с и ~27 MB памяти.
- **Капа кандидатов**: при переполнении пула (CANDIDATE_CAP = 20 000) в скоринг уходит детерминированный равномерный сэмпл по всей базе (шаг `ceil(len/кап)`), поэтому «хвост» инвентаря не теряется и лучший достижимый скор всегда доходит до пользователя. Константа определена в одном месте — `app/generator.py`.
- **Прескоринг и финальный скоринг согласованы**: `_prescore` использует те же веса, что `score_listing` (тот же клампинг 0–100), поэтому выдача стора и итоговый реранк не расходятся. Прескоринг — векторизованный numpy, полный скоринг — пописовый с генерацией reasons.

Бенчмарк (bench.py): сборка 1M — 0.12 с, поиск 4–8 мс на запрос, память +27 MB, детерминизм подтверждён (rebuild даёт идентичные массивы).

## 6. API

- `GET /health` → `{"status": "ok", "dataset_size": N}`
- `POST /lead`, тело `{"inquiry": "<текст заявка>"}` → карточка лида (score, tier, urgency, summary, pipeline_mode, extracted, matches с reasons, agent_notes, listings_screened, listings_matched, candidates_capped)
- `GET /listings?limit=20` → первые листинги инвентаря
- Пустая заявка → HTTP 400 (`empty inquiry`), не 500

## 7. Тесты

49 тестов в `tests/test_pipeline.py` (`unittest`), покрывают: парсинг бюджета (суффиксы, диапазон валидности, «Family of 4» не становится бюджетом), спальни/ванные, типы, районы, срочность, профиль покупателя, разделение must/nice (маркеры внутри клауз), квалификацию (LOW-капа, штраф инвестора), скоринг листингов, работу пайплайна.

## 8. Структура репозитория

```
app/
  data.py        # константы: фичи, типы, регионы + 20 демо-листингов
  pipeline.py    # экстракция, квалификация, скоринг, пайплайн
  generator.py   # синтетический стор на 1M листингов (numpy, seed)
  main.py        # FastAPI: /health, /lead, /listings
  ui.py          # Streamlit-консоль
tests/
  test_pipeline.py

requirements.txt
README.md
```
